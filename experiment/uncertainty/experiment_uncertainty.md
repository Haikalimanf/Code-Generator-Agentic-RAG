# experiment_uncertainty.md

This file provides guidance for understanding and running the uncertainty quantification experiments within this directory (`experiment/uncertainty`).

## Experiment Overview

This experiment is part of a thesis (*skripsi*) focusing on **Uncertainty Quantification in Multi-Agent Systems** using a **Normalized Shannon Entropy (Semantic Clustering)** approach. 

The system measures how input quality (clear instructions vs. ambiguous/aleatoric details) affects the reliability and consistency of requirements generated by the GitLab Analyst Agent. For each issue in the dataset:
1. **Sampling ($M=5$)**: The agent generates 5 different User Story samples at a higher temperature (`temperature=1.0`).
2. **Semantic Clustering**: The samples are preprocessed, embedded using the project's embedding model, clustered based on semantic similarity (using cosine similarity with a configurable threshold), and assigned to semantic groups.
3. **Entropy Calculation**: Discrete Semantic Entropy and Normalized Shannon Entropy (scaled to $0.0 - 1.0$) are calculated to quantify the LLM's uncertainty.
4. **Distribution Visualization**: The scores are plotted on a histogram to identify a Clarification Threshold ($\tau$) that separates confident outputs from uncertain/ambiguous ones.

## Detailed Script Explanations

### 1. [generate_responses.py](file:///d:/RAG/Membuat%20MCP%20Server/experiment/uncertainty/generate_responses.py)
* **Purpose**: Automates the GitLab Analyst Agent to generate $M=5$ samples of User Stories per GitLab issue from the input datasets.
* **Key Mechanisms**:
  - **OpenRouter LLM Setup**: Uses `create_openrouter_llm` running at `temperature=1.0` to encourage response diversity across iterations.
  - **Experimental System Prompt**: Employs `SYSTEM_PROMPT_EXPERIMENT`, which instructs the LLM to choose *one* interpretation of any ambiguity instead of outlining conflicts or listing multiple options. This ensures that when the input has high uncertainty, the LLM will pick different interpretations across runs, generating diverse outputs.
  - **Memory Contamination Prevention**: Uses unique thread IDs per sample (`exp_{dataset}_{issue_id}_samp_{i}`) to prevent LangGraph's agent memory from carrying context over between samples.
  - **Robustness & Checkpoints**: Implements try-except loops with automatic retries (up to 3 times) and dumps generated stories periodically to `response/responses_*.json` to prevent data loss.

### 2. [semantic_clustering.py](file:///d:/RAG/Membuat%20MCP%20Server/experiment/uncertainty/semantic_clustering.py)
* **Purpose**: Clusters the generated User Story samples based on semantic meaning and calculates uncertainty metrics (entropy).
* **Key Mechanisms**:
  - **HuggingFace Embeddings**: Loads the embedding model specified in `settings.rag_embedding_model` (e.g., `BAAI/bge-m3`).
  - **Boilerplate Stripping**: Runs `extract_goal_benefit` to extract only the core goal and benefit text from the User Story. This removes common templates (like `"As a mobile developer, I want..."`), preventing boilerplate from inflating the cosine similarity scores.
  - **Iterative Centroid Clustering**: Compares each response vector against the mean (centroid) vector of existing clusters. If the cosine similarity $\ge$ the threshold (configured at `0.90`), it places the response in that cluster; otherwise, a new cluster is created.
  - **Entropy Scoring**: Computes the Discrete Semantic Entropy and projects it to a Normalized Shannon Entropy score ($0.0 - 1.0$), saving the metrics to `result/scored_*.json`.

### 3. [generate_diagram.py](file:///d:/RAG/Membuat%20MCP%20Server/experiment/uncertainty/generate_diagram.py)
* **Purpose**: Compares the distribution of uncertainty scores between Clear Data and Aleatoric Data to visualize the boundary threshold.
* **Key Mechanisms**:
  - **Pandas Data Merging**: Reads the scored JSON files from `result/`, extracts the `normalized_uncertainty_score` for each test case, and aggregates them into a single DataFrame.
  - **Seaborn Comparative Histogram**: Plots a side-by-side histogram with custom bin width (`0.1`) to show counts per uncertainty range clearly.
  - **Threshold Visualizations**: Renders a vertical line for the Clarification Threshold ($\tau = 0.400$) and overlays transparent color zones for:
    - **SYSTEM IS CONFIDENT** ($\le \tau$): Mostly Clear Data.
    - **SYSTEM IS UNCERTAIN** ($> \tau$): Mostly Aleatoric Data requiring clarification.
  - **Exporting**: Annotates exact counts on top of the bars and saves the output to `result/distribusi_uncertainty_score_histogram.png`.


## Key Experiment & Design Decisions

1. **High-Temperature Sampling**: Running the GitLab Agent with `temperature=1.0` encourages response diversity. If an issue is ambiguous, the high temperature allows the LLM to output varied interpretations across the 5 samples, resulting in higher entropy.
2. **Goal & Benefit Preprocessing**: The system uses `extract_goal_benefit` to isolate the core user story statement (e.g., extracting `"so that users can..."` or similar key parts) before embedding. This removes common boilerplate prefixes (like `"As a mobile developer, I want..."`) which would otherwise artificially inflate cosine similarity scores and skew clustering.
3. **Centroid-Based Clustering**: Responses are clustered iteratively. If a response's cosine similarity to a cluster's current centroid is $\ge$ the threshold (configured at `0.90`), it joins that cluster. Otherwise, it starts a new cluster.
4. **Normalized Shannon Entropy**: The entropy score $U$ is normalized against the maximum possible entropy ($\ln(M)$) to map the final uncertainty score to a $[0.0, 1.0]$ range.
5. **Clarification Threshold ($\tau = 0.400$)**: Determined empirically via visualization. Values $\le 0.400$ designate "SYSTEM IS CONFIDENT", while values $> 0.400$ designate "SYSTEM IS UNCERTAIN" (requiring clarification).

## Environment Variables

The scripts load environmental variables from the main project `.env` file, specifically relying on:
- `OPENROUTER_API_KEY`: API key for calling OpenRouter models.
- `OPENROUTER_BASE_URL`: Base endpoint for OpenRouter.
- `WORKER_MODEL_NAME`: The model used for generation (defaults to `openai/gpt-4o-mini`).
- Centralized configurations defined in `src/config/settings.py` (e.g. `settings.rag_embedding_model` for the HuggingFace embeddings model).
